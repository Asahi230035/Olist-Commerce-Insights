# Olist 电商数据分析项目｜业务指标定义

## 1. 文档目的

本文档统一规定 Olist 电商数据分析项目中的业务指标名称、计算公式、数据来源、统计粒度和过滤条件。

所有 SQL 查询、Python 分析、可视化图表及最终报告应遵循本文件定义。

### 1.1 基本约定

- 数据库：`olist_analysis`
- 订单级数据源：`v_order_analysis`
- 商品明细级数据源：`v_order_item_analysis`
- 客户级数据源：`v_customer_analysis`
- 时间基准：`order_purchase_timestamp`
- 金额单位：沿用原始数据集的货币单位（巴西雷亚尔，BRL）
- 默认时间分组：自然月，格式 `YYYY-MM`
- 订单状态：以 `orders.order_status` 为准

### 1.2 核心统计原则

1. 订单数量使用订单粒度统计，不使用商品明细行数代替。
2. 用户数量使用 `customer_unique_id` 去重。
3. 商品金额与支付金额分别计算，不混用。
4. 经营规模分析优先以已送达订单作为完成交易的代理口径。
5. 退款、平台佣金、利润及真实确认收入无法仅凭当前数据准确计算。
6. 配送分析必须过滤不满足时间有效性要求的记录。
7. 所有比率指标必须明确分子、分母及统计周期。

## 2. 平台经营指标

### 2.1 订单总量（Total Orders）

**定义：** 指定时间范围内创建的订单数量。

**计算公式：**

`订单总量 = COUNT(DISTINCT order_id)`

**数据源：** `v_order_analysis`

**过滤条件：** 按购买时间过滤，默认包含所有订单状态。

**业务用途：** 反映平台订单创建规模。

### 2.2 已送达订单量（Delivered Orders）

**定义：** 订单状态为 `delivered` 的订单数量。

**计算公式：**

`已送达订单量 = COUNT(订单状态为 delivered 的订单)`

**数据源：** `v_order_analysis`

**说明：** 这是已送达订单数量，不直接等同于财务系统确认的已完成交易数量。

### 2.3 已送达商品交易额（Delivered Merchandise Value）

**定义：** 已送达订单中的商品价格合计，不包含运费。

**计算公式：**

`已送达商品交易额 = SUM(item_price_total)`

**过滤条件：** `order_status = 'delivered'`

**数据源：** `v_order_analysis`

**说明：**

本项目将其作为主要经营金额指标，也可以称为已送达商品 GMV 代理指标。

它不等同于严格财务口径下的收入或行业统一口径的 GMV。

不包含退款调整、平台佣金及其他财务项目。

### 2.4 全状态商品交易额

**定义：** 全部订单商品明细中的商品价格合计。

**计算公式：**

`全状态商品交易额 = SUM(item_price_total)`

**过滤条件：** 不限制订单状态。

**数据源：** `v_order_analysis`

**用途：** 用于观察不同订单状态下记录的商品交易规模，不作为默认已完成交易额。

### 2.5 客单价（Average Order Value，AOV）

**定义：** 已送达且存在商品明细的订单，平均每单商品金额。

**计算公式：**

`AOV = 已送达商品交易额 / 已送达且存在商品明细的订单数`

**数据源：** `v_order_analysis`

**过滤条件：**

- `order_status = 'delivered'`
- `has_order_items = 1`

**说明：** 不包含运费，分母不使用商品明细行数。

### 2.6 平均订单运费

**定义：** 已送达且存在商品明细的订单，平均每单运费。

**公式：**

`平均订单运费 = 已送达订单运费合计 / 已送达且存在商品明细的订单数`

**数据源：** `v_order_analysis`

### 2.7 订单取消率

**定义：** 指定时间内创建的订单中，状态为 `canceled` 的比例。

**公式：**

`取消率 = canceled 订单数 / 全部订单数 × 100%`

**数据源：** `v_order_analysis`

**注意：** 数据集记录的是当前可见订单状态。历史月份可能存在状态观察时间不同的问题，不能直接将该指标解释为最终取消概率。

### 2.8 支付金额（Recorded Payment Value）

**定义：** 支付明细表记录的金额合计。

**公式：**

`支付金额 = SUM(payment_total)`

**数据源：** `v_order_analysis`

**说明：**

- 允许一笔订单存在多条支付记录。
- 已在 `v_payments_agg` 中按订单聚合。
- 支付金额不能直接等同于商品交易额。
- 不将记录金额直接解释为最终净收入。

## 3. 商品与地区指标

### 3.1 商品明细数量

**定义：** 指定范围内的商品明细行数。

**公式：**

`商品明细数量 = COUNT(*)`

**数据源：** `v_order_item_analysis`

每行代表一条商品明细。

### 3.2 品类销售额

**定义：** 某商品类别下，已送达订单的商品价格合计。

**公式：**

`品类销售额 = SUM(item_price)`

**分组：** `category_label`

**过滤条件：** `order_status = 'delivered'`

**数据源：** `v_order_item_analysis`

### 3.3 品类销售额占比

**公式：**

`品类销售额占比 = 品类销售额 / 全部品类销售额 × 100%`

所有品类使用相同的订单状态和时间过滤条件。

`unknown` 类别保留在分母中，避免因类别缺失造成金额损失。

### 3.4 地区商品销售额

**定义：** 指定客户所在州或城市对应的已送达订单商品金额。

**公式：**

`地区商品销售额 = SUM(item_price)`

**分组字段：**

- 州：`customer_state`
- 城市：`customer_city`

**数据源：** `v_order_item_analysis`

**注意：** 客户地区与商家地区是两个不同维度，不能混淆。

### 3.5 商家销售额

**定义：** 指定商家关联的已送达订单商品价格合计。

**公式：**

`商家销售额 = SUM(item_price)`

**分组：** `seller_id`

**数据源：** `v_order_item_analysis`

该指标反映商家相关商品交易规模，并非商家实际利润。

## 4. 用户价值指标

### 4.1 累计真实客户数

**定义：** 数据集中不同 `customer_unique_id` 的数量。

**公式：**

`累计真实客户数 = COUNT(DISTINCT customer_unique_id)`

**数据源：** `v_customer_analysis`

### 4.2 月度购买客户数

**定义：** 指定自然月内至少产生一笔已送达订单的真实客户数量。

**公式：**

`月度购买客户数 = COUNT(DISTINCT customer_unique_id)`

**过滤条件：**

- `order_status = 'delivered'`
- 购买时间属于指定月份

**数据源：** `v_order_analysis`

**注意：** 该指标不能等同于平台 MAU，因为数据集没有完整的用户活跃事件。

### 4.3 复购客户

**定义：** 数据观察期内至少存在两笔已送达订单的真实客户。

**判断条件：**

`delivered_orders >= 2`

**数据源：** `v_customer_analysis`

### 4.4 复购率

**定义：** 至少购买成功两次的客户，占至少购买成功一次客户的比例。

**公式：**

`复购率 = 已送达订单数 ≥ 2 的客户数 / 已送达订单数 ≥ 1 的客户数 × 100%`

**数据源：** `v_customer_analysis`

**注意：**

- 此指标采用全数据观察期口径。
- 不应直接使用全部注册或全部下单客户作为分母。
- 受到数据观察窗口长度影响，不等同于固定时间窗口内的留存率。

### 4.5 客户累计商品交易额

**定义：** 一名客户全部已送达订单的商品金额合计。

**字段：** `delivered_item_revenue`

**数据源：** `v_customer_analysis`

不包含运费。

### 4.6 RFM 用户分群指标

本项目采用已送达订单作为 RFM 分析基础。

| 维度 | 定义 | 数据来源 |
|---|---|---|
| R（Recency） | 距离最近一次已送达订单购买时间的天数 | last_delivered_purchase_at |
| F（Frequency） | 数据观察期内已送达订单数 | delivered_orders |
| M（Monetary） | 数据观察期内已送达订单商品金额 | delivered_item_revenue |

**R 计算公式：**

`R = DATEDIFF(分析基准日期, DATE(last_delivered_purchase_at))`

分析基准日期在正式分析时固定，不直接使用运行当天日期。

默认可以采用数据集中最后一个购买日期的次日，确保分析具有可复现性。

未产生已送达订单的客户不参与购买型 RFM 分群，单独保留为无已送达购买记录客户。

RFM 分数阈值在第三阶段根据实际分布制定。

## 5. 配送与履约指标

### 5.1 总配送时长

**定义：** 从客户购买到客户实际签收经历的时间。

**公式：**

`总配送时长 = 实际签收时间 - 购买时间`

**字段：** `delivery_days`

**数据源：** `v_order_analysis`

**过滤条件：** `is_valid_delivery = 1`

单位：天。

### 5.2 平均配送时长

**公式：**

`平均配送时长 = AVG(delivery_days)`

**过滤条件：** `is_valid_delivery = 1`

### 5.3 延迟配送率

**定义：** 在可以判断是否延迟的已送达订单中，实际签收日期晚于预计送达日期的比例。

**公式：**

`延迟配送率 = 延迟送达订单数 / 可判断延迟状态的已送达订单数 × 100%`

**字段：** `is_late_delivery`

**过滤条件：** `is_late_delivery IS NOT NULL`

按日期比较，预计送达当日签收视为按时。

### 5.4 承运商运输时长

**定义：** 从交付承运商到客户实际签收经历的时间。

**公式：**

`运输时长 = 实际签收时间 - 交付承运商时间`

**过滤条件：** `is_valid_transit = 1`

该指标需要在分析 SQL 中根据原始时间字段计算。

### 5.5 配送超期天数

**定义：** 实际签收日期相对预计送达日期晚了多少个自然日。

**公式：**

`配送超期天数 = GREATEST(DATEDIFF(实际签收日期, 预计送达日期), 0)`

**过滤条件：** `is_late_delivery IS NOT NULL`

对于按时或提前签收的订单，超期天数为 0。

## 6. 用户评价指标

### 6.1 平均订单评分

**定义：** 先计算每个订单的有效评价平均分，再对有评分的订单求平均。

**公式：**

`平均订单评分 = AVG(avg_review_score)`

**数据源：** `v_order_analysis`

**过滤条件：** `avg_review_score IS NOT NULL`

**说明：** 这是订单等权平均评分，并非原始评价记录等权平均评分。

订单评分已经在 `v_reviews_agg` 中计算并保留两位小数，因此若需要高精度统计，应从原始评价记录重新聚合。

### 6.2 低评分订单率

**定义：** 平均订单评分不高于 2 分的订单，在具有有效评分的订单中所占比例。

**公式：**

`低评分订单率 = 平均订单评分 ≤ 2 的订单数 / 有效评分订单数 × 100%`

**数据源：** `v_order_analysis`

### 6.3 文字评价率

**定义：** 有效评分订单中，至少包含一条非空评论正文的订单比例。

**公式：**

`文字评价率 = 有文字评价的订单数 / 有效评分订单数 × 100%`

**数据源：** `v_order_analysis`

## 7. 数据质量指标

| 指标 | 定义 | 数据源 |
|---|---|---|
| 订单关联完整率 | 存在商品明细的订单比例 | v_order_analysis |
| 支付记录覆盖率 | 存在支付记录的订单比例 | v_order_analysis |
| 评价记录覆盖率 | 存在评价记录的订单比例 | v_order_analysis |
| 购买至签收时长有效率 | 已送达订单中满足 `is_valid_delivery = 1` 的比例 | v_order_analysis |
| 运输时长有效率 | 已送达订单中满足 `is_valid_transit = 1` 的比例 | v_order_analysis |
| 商品类别缺失率 | 商品类别状态为 `missing_category` 的比例 | v_products_clean |
| 商品类别翻译缺失率 | 商品类别状态为 `missing_translation` 的比例 | v_products_clean |

数据质量指标用于解释分析样本覆盖范围，不直接作为经营绩效指标。

## 8. 指标使用规范

### 8.1 时间口径

经营、商品及客户购买指标默认按订单购买时间归属统计周期。

配送指标可以按购买月份进行分组，但需要注意尚未送达订单带来的样本不完整问题。

跨月比较时，应注意数据集开头和末尾可能存在不完整月份。

### 8.2 金额口径

以下金额必须区分：

- 商品价格合计：不含运费。
- 商品价格加运费：包含商品明细中的运费。
- 支付金额：来自支付明细记录。
- 已送达商品交易额：已送达订单的商品价格合计。

不得将这些金额直接视为相同指标。

### 8.3 统计粒度

| 统计对象 | 推荐数据源 |
|---|---|
| 订单量 | v_order_analysis |
| 客单价 | v_order_analysis |
| 支付金额 | v_order_analysis |
| 商品类别销售额 | v_order_item_analysis |
| 商家销售额 | v_order_item_analysis |
| 客户复购率 | v_customer_analysis |
| RFM | v_customer_analysis |
| 平均订单评分 | v_order_analysis |
| 配送时长 | v_order_analysis |

### 8.4 禁止的统计方式

- 不直接将支付表、评价表、商品明细表进行未经聚合的多表 JOIN 后计算金额。
- 不使用 `customer_id` 代替真实客户唯一标识计算复购。
- 不把商品明细行数直接当作订单数。
- 不把支付金额直接当作商品销售额。
- 不在配送时间异常未处理时直接计算全部订单的配送时长。
- 不将没有访问事件的数据解释为完整的流量漏斗。

## 9. 后续扩展

第三阶段和后续分析阶段可在现有指标基础上扩展：

- 月度环比增长率
- 品类销售集中度
- 地区销售贡献度
- 新老客户购买贡献
- RFM 客户分群
- 延迟配送与低评分关联分析
- 订单金额与评分之间的统计关系

新增指标应先补充到本文件，再用于正式分析与报告。
